# Архитектура

## Правила зависимостей

Слои зависят строго вниз. Нарушение — повод завести отдельный протокол, а не импорт вбок.

```
App/        композиционный корень: сцены, окна, сборка зависимостей
Features/   экранные модули: @Observable-модель + SwiftUI-вью
Terminal/   единственный слой, знающий про GhosttyKit
Services/   git, хуки агентов, персистентность — акторы, без UI
Core/       чистые value-типы, только Foundation
Support/    мелкие расширения
```

## Главное правило

**`import GhosttyKit` разрешён только внутри `Terminal/`.**

Наружу `Terminal/` отдаёт протокол. Причина: авторы libghostty прямо заявляют,
что сигнатуры embedding-API ещё меняются. Когда его сломают, чинить придётся
один каталог. Побочная выгода — остаётся возможность заменить движок
(libghostty-vt со своим рендерером) без переписывания приложения.

Проверять правило так:

```sh
grep -rl "import GhosttyKit" Stanok | grep -v "^Stanok/Terminal/"
```

Пусто — правило соблюдено.

## Управление состоянием

`@Observable` плюс структурированная конкурентность. TCA сознательно не берём:
ядро приложения (поверхность ghostty, PTY, Metal) — императивный
reference-type мир, который в value-type редьюсер не помещается, а цена TCA
окупается объёмом тестов, которого у личного инструмента не будет.

Решение обратимо: TCA композируется в поддерево. Триггер, при котором её
стоит внести в модуль сайдбара — появление третьего асинхронного источника
событий (git-вотчер, хуки агентов, поллинг PR), когда они начнут гоняться
друг с другом.
